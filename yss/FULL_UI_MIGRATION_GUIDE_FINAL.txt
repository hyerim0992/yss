YSS 전체 UI / Eclipse 경로 최종 안내
=====================================
기준 파일: yss(4).zip 실제 프로젝트 구조 확인본
목적: Git 배포 후 팀원이 Eclipse Project Explorer에서 바로 파일을 찾고 작업하기 위한 경로 안내


[0] 제일 먼저 기억할 것
-----------------------
1. 실제로 수정할 소스는 반드시 yss/src/main/... 아래입니다.
2. yss/build/classes/... 는 Eclipse가 만들어 주는 컴파일 결과물이므로 직접 수정하지 않습니다.
3. JSP는 src/main/webapp/WEB-INF/views/... 에 있습니다.
4. CSS / JS / 이미지는 src/main/webapp/dist/... 에 있습니다.
5. WEB-INF/views 아래 JSP는 브라우저에서 JSP 파일 경로로 직접 호출하지 않습니다.
   반드시 Controller URL로 들어갑니다.
6. 현재 Eclipse 프로젝트의 Context Root는 .settings/org.eclipse.wst.common.component 기준 "yss" 입니다.
   따라서 기본 테스트 주소는 http://localhost:8080/yss/... 형태입니다.

브라우저 URL 예)
- 올바름 : /yss/product/detail
- 잘못됨 : /yss/WEB-INF/views/product/detail.jsp

정적파일 예)
- 브라우저 경로 : /yss/dist/css/pages/product/detail.css
- Eclipse 파일   : yss/src/main/webapp/dist/css/pages/product/detail.css

[4] 이미지 / CSS / JS 경로 원칙
-------------------------------
Eclipse 실제 파일 경로
- CSS    : src/main/webapp/dist/css/...
- JS     : src/main/webapp/dist/js/...
- 이미지 : src/main/webapp/dist/images/...
- 폰트   : src/main/webapp/dist/fonts/...

JSP에서 사용할 때
${pageContext.request.contextPath}/dist/...
또는 JSP에 ctx를 선언한 경우 ${ctx}/dist/...

예)
<link rel="stylesheet" href="${pageContext.request.contextPath}/dist/css/pages/product/detail.css">
<script src="${pageContext.request.contextPath}/dist/js/pages/product/detail.js"></script>
<img src="${pageContext.request.contextPath}/dist/images/...">

절대 다시 /resources/... 로 작성하지 않습니다.

[6] Controller에서 JSP 연결하는 방법
------------------------------------
이 프로젝트의 JspView는 자동으로 아래처럼 붙입니다.

Controller에서
return new ModelAndView("product/detail");

실제 forward 대상
/WEB-INF/views/product/detail.jsp

따라서 Controller에서는 아래처럼 쓰지 않습니다.
X return new ModelAndView("/WEB-INF/views/product/detail.jsp");

redirect는
return new ModelAndView("redirect:/main");
처럼 사용하면 Context Path가 자동으로 앞에 붙습니다.


[7] 현재 로그인 Filter에서 꼭 알아둘 경로
-----------------------------------------
파일:
src/main/java/com/yss/filter/LoginFilter.java

현재 비로그인 접근 허용 목록에 포함된 주요 URL
- /main
- /member/login
- /member/logout
- /member/join
- /product/**
- /customer/contact
- /dist/**

중요 확인사항 1)
현재 허용 목록에는 정확히 "/order" 만 들어 있고 "/order/**" 가 아닙니다.
따라서 현재 코드 그대로면 비로그인 사용자가
/order/agreement, /order/checkout, /order/complete 에 접근할 때 로그인 화면으로 이동합니다.
비회원 주문을 실제 구현할 예정이면 주문 담당자가 LoginFilter의 허용 범위를 반드시 검토해야 합니다.

중요 확인사항 2)
관리자 URL에 접근한 로그인 사용자의 role이 5 미만이면
/member/noAuthorized 로 redirect 하도록 되어 있습니다.
그러나 yss(4) 현재 Controller에는 /member/noAuthorized Mapping이 없습니다.
관리자 권한 화면을 실제 사용할 때 추가 구현 또는 redirect 경로 수정이 필요합니다.


[8] 현재 프로젝트에서 경로 때문에 헷갈리기 쉬운 파일
------------------------------------------------------
1) 아래 파일은 존재하지만 현재 JSP에서 로드하지 않는 이전/중복 JS입니다.
- src/main/webapp/dist/js/member/login.js
- src/main/webapp/dist/js/member/join.js

따라서 회원 화면 JS 수정 시 pages/member/... 쪽을 수정합니다.

2) src/main/webapp/WEB-INF/views/member/logout.jsp
- 파일은 존재하지만 현재 /member/logout Controller는 이 JSP를 사용하지 않고 redirect 합니다.

3) src/main/webapp/WEB-INF/views/admin/home/main.jsp
- 파일은 존재하지만 현재 HomeManageController에서 연결된 Mapping이 없습니다.
- 실제 관리자 대시보드는 admin/dashboard/main.jsp 입니다.


[9] Git 시작 전에 꼭 공유할 충돌 위험 파일
------------------------------------------
현재 UI 구조상 아래 두 파일은 여러 담당 기능이 한 파일에 모여 있습니다.

A. 마이페이지
src/main/webapp/WEB-INF/views/mypage/mypage.jsp
src/main/webapp/dist/js/pages/mypage/mypage.js
src/main/webapp/dist/css/pages/mypage/mypage.css

B. 고객센터
src/main/webapp/WEB-INF/views/customer/contact.jsp
src/main/webapp/dist/js/pages/customer/contact.js
src/main/webapp/dist/css/pages/customer/contact.css

여러 명이 같은 날 같은 파일을 수정하면 merge conflict가 날 가능성이 높습니다.
각자 기능은 나눠도 현재 물리 파일은 하나이므로,
작업 전 pull -> 담당 구간 수정 -> commit/push -> 다음 담당 pull 순서를 지키거나
추후 JSP/JS를 기능별 partial 파일로 분리하는 방식이 안전합니다.
